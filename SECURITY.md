# Security Policy

## Supported version

Security fixes are applied to the latest `main` branch.

## Reporting a vulnerability

Do not open a public issue for a vulnerability, credential exposure, authorization bypass, report-data leak, or unsafe calculation behavior. Use GitHub’s **Report a vulnerability** feature to create a private security advisory for this repository.

Include a concise reproduction, impact, affected files or routes, and any suggested mitigation. Never include active credentials or real user report data in the report.

## Privacy-sensitive areas

Treat authentication, owner-scoped report retrieval, signed storage URLs, generated PDFs, artifact retention, child-process input handling, and translation prompts as privacy-sensitive code paths.
